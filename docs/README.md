## Current project state

Stated up front so these documents are not mistaken for a description of finished software.

### Working

- Four models (`Student`, `HealthRecord`, `Consultation`, `HealthStatus`) with foreign keys, indexes,
  and `ON DELETE CASCADE`
- Five viewsets under `/api/` — full CRUD, plus a read-only Student Portal surface and nested
  per-student routes
- Migration chain `0001` → `0005`, including a data migration that split consultations out of health
  records
- Custom DRF exception handler producing a uniform `{success, status_code, errors}` envelope
- Session authentication endpoints (`csrf`, `login`, `logout`, `me`)
- Django Admin with inlines for all four models — **the only working user interface**
- OpenAPI schema generation, Swagger UI, and ReDoc
- **54 automated tests, all passing**

### Not built

- **The frontend UI.** `frontend/src/App.jsx` is the unmodified Vite + React starter — a demo counter,
  template logos, and links to Vite and React. No clinic screen, no API calls, no routing, no state
  management.
- **Frontend-to-backend wiring.** `vite.config.js` configures no dev-server proxy and no API base URL.
- **Screenshots and a design system.** No screens exist to capture, and no design system or Figma file
  is referenced anywhere in the repository.
- **A Registrar integration.** Student IDs are supplied by the caller; there is no inbound feed.
- **API authentication enforcement.** Global permissions are `AllowAny`.

### Known defects

Recorded in [architecture.md §6.3](architecture.md#63-known-defects-found-while-verifying-this-document):

1. `?search=` on `/api/health-records/` raises `FieldError` — it filters on a reverse relation that
   belongs to `Student`, not `HealthRecord` (`views.py:283`). Untested, so the suite still passes.
2. `urlpatterns` is assigned twice in `backend/config/urls.py`; the first block is dead code.
3. `ALLOWED_HOSTS` defaults to include a `*` wildcard.
4. `.env.example` lists CORS origins that `settings.py` does not read — the CORS list is a hardcoded
   literal.
5. `SECRET_KEY` has a hardcoded fallback identical to the shipped `.env.example` value.
6. Non-numeric `?search=` on students returns the unfiltered list instead of nothing.
7. `gen/` is a stale generated client that predates the Consultation split.

### Stale generated client

`gen/` was produced by openapi-generator 7.7.0 **before** the Consultation split. Its `HealthRecord`
model still carries the removed `visit` and `consultation` fields, and it has no `Consultation` or
`HealthStatus` client. Do not treat it as the current contract — see
[data-model.md §9](data-model.md#9-mock-data--generated-client-drift).

## Conventions used in these documents

- **Every claim is traceable to a file.** Model fields cite `models.py` line numbers; endpoints cite
  `views.py`; configuration cites `settings.py`. Where something is absent, it is stated as absent
  rather than filled in with an intention.
- **No aspirational content.** Where a template would have described planned features, these documents
  state plainly that the feature does not exist.
- **Verified figures.** The test count (54) comes from an actual `python manage.py test clinic` run,
  not from a count in the previous README.
- **Defects are documented, not silently corrected.** This documentation pass changed no application
  code.
